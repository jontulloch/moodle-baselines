# 08 No copyrighted files

It is very easy to find yourself uploading to Moodle PDFs or other resources that you have downloaded from the internet or from journals. Unfortunately, this is a very risky thing to do, because there is a good change those files are copyrighted and remain the intellectual property of the people who wrote them. By uploading them to Moodle for students, you are therefore effectively redistributing copyrighted material - which is illegal. By far the safer thing to do is to use the comprehensive library tools available to link to the resource instead. It is therefore a minimum standard to ensure that there are no such files on your course page, and this report is designed to help you ensure this.

### What it does

The report scans the course page and checks the filename of any PDF or Doc resources that have been uploaded. It is important to note that it looks only for the name of the uploaded file, not the name of the activity itself. For example, a file that includes ‘et al’ will be identified, even if the activity is renamed:


![](/assets/gitbook/image-66.png)


Conversely, a resource will not be identified if the filename contains no indicative markers, even if the name of the activity uses a standard citation format:


![](/assets/gitbook/image-67.png)


The report searches for patterns in filenames that may indicate a copyrighted original. These patterns include:



**Publisher sources**

Files linked from platforms like JSTOR, ScienceDirect, Wiley, Springer, etc.



**DOIs (Digital Object Identifiers)**

Filenames containing DOI patterns or the word “doi”



**Academic citation patterns**

Filenames that resemble references, such as:

* Author names (e.g. Smith and Jones)
* “et al.”
* A publication year (e.g. 2022 or (2022))
* Combined patterns like:
  * Author(s) + Year + Title
  *

**Year indicators in filenames**

Especially when combined with other academic cues



This is a heuristic check, not a definitive copyright assessment. It highlights files that _look_ like published academic content so you can review them and, where appropriate, replace them with links to the original source. This means that the algorithm may make false positives where non-copyrighted files match the coded markers.

If a file is identified that matches the coded markers and it is **visible** to students, then it will be displayed in a yellow warning box and the requirements for the minimum standard will **not be met**. The title of the resource functions as a link that will take users directly to the resource in question. Additionally, there is a ‘hide’ icon next to the title. Clicking on this icon will automatically hide the resource from students and take users back to the course main page. And there is a ‘delete’ icon that will take users to a page where they can confirm whether they want to delete the resource.


![](/assets/gitbook/image-68.png)


If a file is identified that matches the coded markers and it is **hidden** to students, then this file will not prevent the standards from being met. It will be displayed in a grey box and will require no action:


![](/assets/gitbook/image-69.png)


If no matching files are identified, then the report will return just a green box telling users that there are no identified files and the the conditions of the minimum standard have been met.


![](/assets/gitbook/image-70.png)


### How to use it

In order to meet the criteria for the minimum standard, the report needs to have no yellow warning messages. If you see a yellow warning message, it indicates that a file has been found that matches the markers for potentially copyrighted resources. The yellow box firstly indicates that the file is ‘visible to students’ and then has the full title of the file. You can click this file name to be taken straight to the resource itself. Beneath the file name you will see a short explanation of why the file has been identified.


![](/assets/gitbook/image-71.png)


It is important to note that the file name represents **the name of the uploaded file not the name of the activity as set on the Moodle course page**. If you have changed the name of the activity, that name will not appear here. At the same time, it is important to note that the report will **only show pdf and doc files**. Uploaded PowerPoint or other types of files will not be listed.

There are two immediate options to deal with any identified files, and these are available as icons next to the file name. Here you will see a hidden eye icon for ‘hide’, and a dustbin icon for 'delete:


![](/assets/gitbook/image-72.png)


If you click on the ‘hide’ icon, the resource will automatically be set to ‘hidden from students’. The main course page will open, enabling you to check the status of the activity. If you click on the ‘delete’ icon you will be taken to a page where you will be asked to confirm whether you want to delete the resource or not. Clicking on ‘yes’ will delete the activity from your course page.


![](/assets/gitbook/image-73.png)


If the report has identified a file, and that file is hidden from students, then there is no further action required in order to meet the minimum standards for the course page. The hidden file will still show on the report page, but it will appear as greyed out. You still have the option to delete this resource using the ‘delete’ icon next to it:


![](/assets/gitbook/image-74.png)


If the report has identified a copyrighted resource that you still need to provide for students, there is a link in the green box that will direct you to your **subject librarian**:


![](/assets/gitbook/image-75.png)


This link will take you to a SharePoint page where you will see contact information for all the subject librarians in the University library. You can contact one of these specialists, and they can advise you on how to make the resource legally available for students:


![](/assets/gitbook/image-76.png)
